7. Nginx dan HTTPS

Nginx meneruskan request ke API lokal 127.0.0.1:3001 dan mendukung WebSocket Socket.IO. Sebelum mengubah konfigurasi:

sudo nginx -t
sudo systemctl reload nginx

Sertifikat Let’s Encrypt diterbitkan untuk API:

sudo certbot --nginx -d api.joelid.hontalk.my.id --redirect
curl -I https://api.joelid.hontalk.my.id/api/v1/health

Pastikan renewal otomatis tersedia:

sudo systemctl list-timers | grep certbot
sudo certbot renew --dry-run

8. Vercel

  • Repository: hafourenai/AE-Capstone.
  • Build hanya workspace web melalui vercel.json; backend SQLite tidak ikut dibuild di Vercel.
  • Environment Variable: VITE_API_BASE_URL=https://api.joelid.hontalk.my.id/api/v1.
  • Custom domain: joelid.hontalk.my.id.

Jika build Vercel gagal karena better-sqlite3, pastikan deployment mengambil commit yang memuat vercel.json dan redeploy. Penyebabnya adalah Vercel mencoba memasang dependency backend native, padahal hanya frontend yang perlu dibuild.

9. Backup SQLite

Skrip backup: ops/backup-sqlite.sh. Metodenya memakai sqlite3 .backup, aman untuk database dalam mode WAL. Jangan hanya menyalin file .sqlite aktif.

sudo install -m 750 ops/backup-sqlite.sh /usr/local/bin/sambal-joelid-backup
sudo install -m 644 ops/sambal-joelid-backup.service /etc/systemd/system/
sudo install -m 644 ops/sambal-joelid-backup.timer /etc/systemd/system/
sudo systemctl daemon-reload
sudo systemctl enable --now sambal-joelid-backup.timer
sudo systemctl list-timers | grep sambal
sudo systemctl start sambal-joelid-backup.service
ls -lh /var/backups/sambal-joelid
Penting: backup terjadwal lokal saja belum memenuhi proteksi bencana. Salin backup terenkripsi ke storage berbeda (misalnya object storage) dan uji restore secara berkala.

Fase implementasi

  1. Keputusan dan keamanan. Tetapkan provider AI, nomor WhatsApp bisnis khusus, format pesan, batas eskalasi ke admin, serta kebijakan privasi. WAHA berbasis WhatsApp Web; gunakan sesuai ketentuan WhatsApp dan pahami risiko logout/pembatasan nomor.
  2. WAHA terisolasi. Pasang Docker khusus WAHA, gunakan image resmi devlikeapro/waha, persistent volume, health check, API key, dan binding hanya ke 127.0.0.1:3000. Port 3000 tidak dibuka di UFW dan tidak diproxy ke publik.
  3. Webhook aman. Tambahkan endpoint WAHA di API dengan shared secret/signature, idempotency berdasarkan message ID, payload-size limit, allowlist event, dan log metadata tanpa isi pesan sensitif berlebihan.
  4. AI response. Tambahkan service provider AI dengan timeout, retry terbatas, rate limit per nomor, prompt kebijakan, dan fallback pesan aman bila AI/provider tidak tersedia.
  5. Order dan keluhan. AI hanya mengekstrak draft terstruktur. Backend tetap memverifikasi cabang, menu, kuantitas, harga, total, transisi status, lalu memakai service SQLite yang sama dengan form web. AI tidak boleh mengarang harga, mengakses catatan internal, atau mengonfirmasi transaksi yang gagal disimpan.
  6. Human handoff. Sediakan kata kunci seperti admin/operator, status percakapan, dan penanda agar AI berhenti membalas ketika admin mengambil alih.
  7. Dashboard. Tambahkan sumber kanal WEB/WHATSAPP, ringkasan percakapan yang aman, dan realtime event tanpa mengekspos pesan pelanggan kepada user tidak berwenang.
  8. Pengujian. Uji QR/session WAHA, webhook valid/tidak valid, deduplikasi, pesan biasa, draft order, keluhan, AI outage, restart container, restart API, serta event realtime dashboard.
  9. Operasional. Monitoring health WAHA/API, backup session sesuai kebutuhan, rotasi API key, prosedur reconnect QR, dan dokumentasi rollback.

Keputusan yang dibutuhkan sebelum coding

  • Provider AI: Gemini API, OpenAI API, atau provider lain.
  • Nomor WhatsApp khusus yang akan dipasangkan ke WAHA.
  • Bahasa, nada jawaban, jam operasional, dan kondisi wajib handoff ke admin.
  • Apakah order dari WhatsApp langsung dibuat setelah pelanggan mengonfirmasi ringkasan, atau selalu menunggu admin.
Aturan utama: jangan menaruh token WAHA, credential AI, QR/session WAHA, atau secret webhook dalam repository atau frontend Vercel.
