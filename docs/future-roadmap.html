02

1. Integrasi Payment Gateway (QRIS Otomatis)

Saat ini order WhatsApp berstatus NEW dan memerlukan konfirmasi pembayaran manual oleh kasir/admin. Tahap berikutnya adalah penerbitan QRIS instan.

PROVIDER PILIHAN

Midtrans / Xendit / Tripay

Mendukung webhook notifikasi pembayaran dan pembuatan QRIS / Virtual Account dinamis secara realtime.

ALUR PENGGUNA

Direct-in-Chat Checkout

Setelah pelanggan balas YA, bot langsung mengirim gambar QRIS dinamis dan link pembayaran.

Spesifikasi Alur Teknis:

Pelanggan konfirmasi "YA"
  ↓
Express memanggil Payment Gateway API (Create QRIS Transaction)
  ↓
WAHA mengirim gambar QRIS + batas waktu bayar (misal 15 menit)
  ↓
Pelanggan scan QRIS & bayar via m-Banking/E-Wallet
  ↓
Webhook Payment Gateway → Express /api/v1/integrations/payment/webhook
  ↓
Order status berubah: PAID → Notifikasi otomatis ke dapur & pelanggan
Keuntungan: Kasir tidak perlu cek mutasi rekening satu per satu, mengurangi risiko order fiktif, dan pesanan dapat langsung dialihkan ke status antrean dapur.

03

2. Manajemen Stok Menu & Multi-Cabang Realtime

Mencegah pesanan masuk ketika stok sambal atau menu ayam di cabang tertentu sudah habis (out of stock).

  • Kolom ketersediaan (is_available / stock_qty): Tabel branch_menus untuk tracking status aktif/habis per menu per cabang.
  • Inject context stok ke Prompt AI: AI hanya merekomendasikan dan memproses menu yang statusnya tersedia di cabang yang dipilih pelanggan.
  • Dashboard Kasir Sederhana: Tombol toggle 1-klik untuk kasir/admin cabang mematikan menu ("Ayam Geprek Cabang Pusat: HABIS").
  • Routing Pesanan ke Printer / Tab Cabang: Mengirim payload pesanan langsung ke layar antrean cabang tujuan via Socket.IO.

04

3. Peningkatan Kapabilitas AI (RAG & Function Calling)

Meningkatkan model lokal atau hybrid agar tidak hanya membaca katalog statis, namun juga dapat mengakses data transaksi dan informasi operasional terkini.

Fitur Deskripsi Implementasi Dampak Bisnis
Live Order Tracking Pelanggan chat: "Cek status pesanan ORD-12345" → AI memanggil tool backend untuk mengambil status terkini (SEDANG DIMASAK / DALAM PENGANTARAN). Mengurangi 70% beban admin menjawab pertanyaan tracking order.
RAG Knowledge Base Mengambil potongan dokumen FAQ (promo hari ini, alergen, syarat pengiriman, lokasi parkir) secara semantik sebelum memanggil model. Jawaban akurat tentang detail kebijakan restoran tanpa meluberkan konteks prompt.
Upgrade Model / Dual Engine Opsi fallback otomatis ke model cloud (misal Groq / Claude / OpenAI) jika Termux lokal offline atau traffic lonjakan tinggi. Zero-downtime pelayanan pelanggan bahkan saat perangkat lokal restart.

05

4. Proactive WhatsApp Notifications (Outbound Flow)

Memanfaatkan WAHA untuk mengirimkan notifikasi status transaksi secara proaktif kepada pelanggan tanpa menunggu pelanggan bertanya.

[Trigger di Kitchen/Admin Dashboard]
Order diubah ke status "SIAP_DIAMBIL" atau "SEDANG_DIKIRIM"
  ↓
Express memicu WAHA Service (sendMessage ke saved chat_id @lid)
  ↓
Pesan WhatsApp otomatis terkirim:
"Pesanan Anda ORD-12345 sedang diantar oleh kurir! 🛵
Estimasi tiba: 15-20 menit."

06

5. Keamanan, Ketahanan & Skalabilitas Infrastruktur

  • Migrasi SQLite ke PostgreSQL: Jika volume pesanan dan chat harian meningkat drastis, pisahkan database ke PostgreSQL terkelola dengan connection pooling.
  • Redis Queue untuk Webhook: Gunakan antrean (BullMQ/Redis) untuk webhook WAHA inbound agar pesan berurutan rapi dan tidak membebani CPU saat peak hour.
  • Automated Offsite Backup: Sinkronisasi file backup SQLite terenkripsi secara otomatis ke S3 / Cloudflare R2 setiap tengah malam.
  • Rate Limiting per Nomor WA: Mencegah spam pesan berulang atau percobaan flooding prompt ke model LLM.
